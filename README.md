# SupportDesk AI — Hybrid NLP Customer Service Chatbot

A production-style customer service chatbot that combines a **trained NLP intent classifier**
(TF-IDF + Logistic Regression) with a **rule-based business logic layer** (entity extraction,
slot-filling, mock order lookups). Built as part of an AI/ML internship project at
**Codec Technologies**.

Unlike a purely rule-based bot (rigid, keyword-only) or a purely ML bot (a black box that can't
reliably act on real data), this project uses the hybrid pattern many real support bots use in
production: **ML for language understanding, rules for anything that touches real business data.**

---

## Features

- **NLP intent classification** — a scikit-learn pipeline (TF-IDF vectorizer + Logistic
  Regression) trained on 19 customer-service intents (order status, returns, refunds, payment
  issues, shipping, complaints, escalation to a human agent, etc.)
- **Custom lightweight text preprocessing** — lowercasing, contraction expansion, punctuation
  stripping, stopword filtering that *preserves negations*, and a small rule-based stemmer —
  built from scratch with no heavyweight NLP downloads required.
- **Rule-based entity extraction** — regex-based extraction of order IDs and emails from free text.
- **Slot-filling / multi-turn context** — if a user asks "where's my order?" without an ID, the
  bot remembers it's waiting for one and completes the lookup on the next message.
- **Confidence-threshold fallback** — low-confidence predictions trigger a clarifying response
  instead of a wrong answer.
- **Mock order database** — believable, varied responses for demo purposes without needing a
  real backend.
- **Two interfaces**: a **Flask REST API + web chat UI**, and a **command-line chat mode**.
- **Conversation logging** — every exchange is logged to `data/conversation_logs.jsonl` for
  later analysis (a common real-world requirement for support bots).
- **Analytics dashboard endpoint** (`/api/analytics` + `src/analytics.py`) — summarizes logged
  conversations into intent frequency, average confidence per intent, and fallback rate, so a
  support team can see what customers actually ask about and where the bot struggles. Not part
  of the original brief, but a genuinely necessary piece of any real deployment.
- **Configurable via environment variables** (`PORT`, `FLASK_DEBUG`, `CONFIDENCE_THRESHOLD`) —
  see `.env.example`.
- **Dockerized** — `Dockerfile` + `docker-compose.yml` for a one-command run anywhere.
- **CI pipeline** (`.github/workflows/tests.yml`) — runs the full test suite on every push/PR
  across Python 3.10 and 3.11.
- **Unit tests** (22 total) covering NLP utilities, end-to-end conversation flows, and analytics.

## Architecture

```
User message
     │
     ▼
┌─────────────────────────┐
│ 1. Context / Slot check │  <- are we mid-conversation, awaiting an order ID?
└────────────┬────────────┘
             │ no
             ▼
┌─────────────────────────┐
│ 2. NLP preprocessing    │  <- clean_text, tokenize, stem, stopword removal
│    (src/nlp_utils.py)   │
└────────────┬────────────┘
             ▼
┌─────────────────────────┐
│ 3. Intent classifier     │  <- TF-IDF + Logistic Regression
│    (models/*.joblib)    │      confidence < 0.35 -> fallback
└────────────┬────────────┘
             ▼
┌─────────────────────────┐
│ 4. Rule-based business   │  <- regex entity extraction, slot-filling,
│    logic (chatbot.py)   │      mock order DB lookups
└────────────┬────────────┘
             ▼
        Bot response
```

## Getting started

### 1. Install dependencies

```bash
python -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate
pip install -r requirements.txt
```

### 2. Train the intent classification model

```bash
python src/train_model.py
```

This reads `data/intents.json`, trains a TF-IDF + Logistic Regression pipeline, prints a
held-out classification report, and saves the model to `models/intent_classifier.joblib`.

### 3a. Run the web app

```bash
python src/app.py
```

Open **http://localhost:5000** in your browser and start chatting.

### 3b. Or run the CLI version

```bash
python src/chatbot.py
```

```
Chatbot ready. Type 'quit' to exit.

You: where is my order
Bot [order_status | conf=0.8]: Sure, I can help with that. Could you please share your order ID (e.g. ORD12345)?
You: ORD12345
Bot [slot_filling | conf=1.0]: Order ORD12345 is currently **Shipped** (carrier: BlueDart, ETA: 2 business days).
```

### 4. Run the tests

```bash
pytest tests/ -v
# or, without pytest:
python -m unittest discover tests -v
```

### 5. View conversation analytics

```bash
python src/analytics.py          # console report
# or, with the app running:
curl http://localhost:5000/api/analytics
```

## Deployment

The app ships with `gunicorn` (production WSGI server), a `Procfile`, and a `render.yaml`
blueprint, so it's ready to deploy as-is — no extra setup needed beyond picking a host.

### Option A — Render (easiest, free tier, recommended)

1. Push this repo to GitHub (see below).
2. [render.com](https://render.com) → **New** → **Blueprint** → connect your repo. Render reads
   `render.yaml` automatically and configures the build/start commands.
3. Or configure manually: **New → Web Service**, connect the repo, and set:
   - Build command: `pip install -r requirements.txt && python src/train_model.py`
   - Start command: `gunicorn --chdir src app:app --bind 0.0.0.0:$PORT`
4. Deploy. Render gives you a public URL like `https://supportdesk-ai.onrender.com`.

### Option B — Railway

1. [railway.app](https://railway.app) → **New Project** → **Deploy from GitHub repo**.
2. Railway auto-detects the `Procfile`. The trained model (`models/intent_classifier.joblib`)
   is already committed, so no build-time training step is required.
3. Deploy — Railway assigns a public URL automatically.

### Option C — Docker anywhere (Fly.io, a VPS, AWS/GCP/Azure, etc.)

```bash
docker build -t supportdesk-ai .
docker run -p 5000:5000 -e FLASK_DEBUG=0 supportdesk-ai
```

Push the built image to any container registry and run it on Fly.io, AWS App Runner/ECS,
Google Cloud Run, or a plain VPS with Docker installed. Cloud Run and Fly.io need the least
configuration for a small Flask app like this.

### Option D — PythonAnywhere (no CLI/Docker needed, good for a first deploy)

1. Upload the project or clone the GitHub repo via their web-based console.
2. Create a virtualenv, `pip install -r requirements.txt`, run `python src/train_model.py`.
3. Configure a new **Web app** → Manual config → Flask, pointing the WSGI file at `src/app.py`'s
   `app` object.

**Important for any host:** set `FLASK_DEBUG=0` in production. The Flask dev server's debug
mode exposes an interactive in-browser debugger that must never be public-facing.

## Tech stack

- **Python 3**, **scikit-learn** (TF-IDF vectorizer, Logistic Regression)
- **Flask** for the REST API and web UI
- **joblib** for model persistence
- Vanilla **HTML/CSS/JS** front end (no framework dependency)
- **unittest** for testing

## Design decisions & possible extensions

- The dataset (`data/intents.json`) is intentionally small and hand-curated so it's easy to
  read, extend, and retrain — add new patterns/intents and re-run `train_model.py`.
- The mock order database in `chatbot.py` stands in for a real order-management API; in
  production, `_handle_order_id_followup` would call a real service instead.
- Possible extensions: swap Logistic Regression for a transformer-based intent classifier,
  add a real database, add authentication, deploy behind Gunicorn/Nginx, or add multi-language
  support.
